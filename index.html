Architecture

The database is the app.

No application server. Postgres holds the routing, the simulation engine and every screen of the console as PL/pgSQL. PostgREST turns those functions into HTTP; nginx serves the static files.

Postgres the application — routing, sim engine, every screen
PostgRESTfunctions → HTTP
nginxstatic files
  • Three containers, one command. make up and the database installs itself on first boot.
  • Ported, then proven. Diffed against the stack it replaced before that stack was retired: 11 of 11 screens byte-identical, 50 of 50 routing decisions identical.
  • No supply chain to babysit. No npm, no bundler; a handful of pinned single-file libraries.

The console

Built by someone who does the work.

Drag, drop, done

Self-host

Your server. Your data.

Docker brings up Postgres, PostgREST and nginx, and a fresh database installs the app and a demo day on first boot. Prefer no Docker? The SQL, the PostgREST binary and an nginx config are all it needs.

$ git clone https://github.com/sys-ae/fieldopt
$ cd fieldopt && make up
# → http://localhost:8081
